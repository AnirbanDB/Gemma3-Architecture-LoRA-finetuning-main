# Gemma 3 — Implementation and LoRA Fine-Tuning from Scratch

A 270M-parameter **Gemma 3** language model built from the tensor up in PyTorch, pre-trained on
TinyStories, then instruction-tuned with a **hand-written LoRA implementation**.

No `transformers`, no `peft`. Every component — RMSNorm, rotary embeddings, grouped-query
attention, sliding-window masks, the GeGLU feed-forward, and the low-rank adapters — is written
out explicitly.

## Architecture

The model follows the HuggingFace Gemma 3 reference implementation.

| Component | Detail |
| --- | --- |
| **RMSNorm** | Zero-centred weight applied as `(1 + w)`; reduction forced to float32 |
| **Rotary embeddings** | Two schedules — `theta=10_000` for local layers, `theta=1_000_000` for global |
| **Attention** | Grouped-query attention, 4 query heads sharing 1 KV group, with QK-norm |
| **Masking** | Sliding-window local attention (512) interleaved with full attention (layers 5, 11, 17) |
| **Feed-forward** | GeGLU — two parallel expansions, one gating the other via tanh-approximated GELU |
| **Block** | Sandwich normalization: four RMSNorms per layer, wrapping each sublayer in and out |

### Configuration (`GEMMA3_CONFIG_270M`)

| Key | Value |
| --- | --- |
| `vocab_size` | 50,257 (GPT-2 BPE) |
| `context_length` | 32,768 |
| `emb_dim` | 640 |
| `n_layers` | 18 |
| `n_heads` / `n_kv_groups` | 4 / 1 |
| `head_dim` | 256 |
| `hidden_dim` | 2,048 |
| `sliding_window` | 512 |
| `qk_norm` | `True` |
| `dtype` | `bfloat16` |

## Pipeline

```
TinyStories ──▶ GPT-2 BPE ──▶ train.bin ──▶ pre-training (17k iters, all 270M params)
                                                    │
                                          best_model_params.pt
                                                    │
                                                    ▼
Alpaca instruction data ──▶ collate ──▶ LoRA fine-tuning (10 epochs, adapters only)
```

### 1. Pre-training

Corpus is [TinyStories](https://huggingface.co/datasets/roneneldan/TinyStories), tokenized with
GPT-2 BPE via `tiktoken` and written to a flat `uint16` memmap (data pipeline adapted from
[nanoGPT](https://github.com/karpathy/nanoGPT)).

| Setting | Value |
| --- | --- |
| Iterations | 17,000 |
| Batch × block | 32 × 128 |
| Gradient accumulation | 32 (effective batch 1,024 sequences) |
| Optimizer | AdamW, β (0.9, 0.95), weight decay 0.1 |
| Schedule | Linear warmup (1,000) → cosine decay |
| Gradient clipping | `max_norm` 0.5 |

### 2. LoRA fine-tuning

`LoRALinear` wraps a frozen `nn.Linear` and adds `base(x) + (x @ A @ B) * (alpha/rank)`.
`A` is Kaiming-initialized and `B` is zeroed, so the wrapped model is **exactly** the pre-trained
model at step 0 while the adapter path still receives gradient.

`add_lora_to_gemma3` freezes every parameter, then wraps seven projections per block —
`W_query`, `W_key`, `W_value`, `out_proj`, `fc1`, `fc2`, `fc3` — across all 18 blocks
(126 wrapped projections). Embeddings, the output head and all RMSNorms stay frozen.

| Setting | Value |
| --- | --- |
| Rank / alpha | 8 / 16 |
| Epochs | 10 |
| Batch size | 8 |
| Learning rate | 5e-5 |
| Dataset | 1,100 Alpaca-format entries (85 / 10 / 5 split) |

Instruction data and LoRA scaffolding follow
[rasbt/LLMs-from-scratch](https://github.com/rasbt/LLMs-from-scratch).

```bash
git clone https://github.com/AnirbanDB/Gemma-3-Implementation-and-LoRA-Fine-Tuning-from-Scratch.git
cd Gemma-3-Implementation-and-LoRA-Fine-Tuning-from-Scratch

pip install -r requirements.txt

jupyter notebook gemma3-270b-from-scratch-lora-finetuning.ipynb
```

Run the cells in order. A CUDA GPU is effectively required — the notebook was developed on a
Tesla T4. Note that cells 29 and 34 load the checkpoint from a Kaggle mount path:

```python
best_model_params_path = "/kaggle/input/gemma3-parameters/best_model_params.pt"
```

Change this to `"best_model_params.pt"` when running locally.

Weights, tokenized `.bin` files and the downloaded instruction dataset are gitignored — they are
all regenerated by running the notebook.

## Results

### After pre-training

```
Input:  "Once upon a time there was a pumpkin."
Output: "Once upon a time there was a pumpkin. It was who wanted to see his heart also sad.
         Todd right bubbles with a Anna and juicy! Once upon a time there was a sail.
         The house and's dance dog..."
```

The model produces locally coherent sentences but degrades into repetitive, semi-nonsensical
text. This is expected — the model has learned TinyStories' register and vocabulary but not
long-range structure at this scale of training.

### After LoRA fine-tuning

```
Instruction: Rewrite the sentence using a simile.
Input:       The car is very fast.
Response:    The moral of the word, the little girl is ' is ' is ' is 'I'm sorry.

Instruction: Name the author of 'Pride and Prejudice'.
Response:    The moral of ' is 'You're welcome, and 'You're welcome...
```

The model fails to follow instructions and collapses into repetitive patterns.

---

## Why the results look like this

- **Domain mismatch.** The base model saw only children's stories. Nothing in TinyStories
  resembles `### Instruction:`, so the adapter has to teach an entirely new register rather than
  adapt a familiar one.
- **Small dataset.** ~935 training examples is far below what instruction-following needs; the
  adapter memorizes surface tokens instead of the task.
- **LoRA's limited capacity.** Rank 8 across 126 projections is roughly 1M trainable parameters
  against 270M frozen. LoRA steers a competent model — it cannot install a capability the base
  model lacks.
- **Greedy decoding.** Final evaluation calls `generate` at `temperature=0.0` with no `top_k`.
  Argmax over a low-confidence distribution locks into the highest-probability cycle, which is
  exactly the repetition seen above.

## Known issues and improvements

- `min_lr = 5e-4` is larger than `learning_rate = 1e-4`, so `CosineAnnealingLR`'s `eta_min`
  floor sits above the peak and the cosine leg anneals *upward*. Set `eta_min` below the peak LR.
- `sliding_window = 512` against `block_size = 128` means no query is ever more than 127
  positions from a key, so the sliding-window path is never exercised during training. Raising
  the context to 512+ would make the local/global split real.
- The loss is computed over the full sequence, including the prompt. Masking everything before
  `### Response:` would concentrate gradient on the part that matters.
- Cell 70 rebuilds the optimizer without the `requires_grad` filter from cell 42. The LoRA
  contract still holds (base weights are frozen), but AdamW allocates optimizer state for every
  frozen parameter.
- `download_and_load_file` disables TLS verification (`check_hostname=False`, `CERT_NONE`) as a
  Kaggle-environment workaround. Remove it when running elsewhere.
- Evaluating with `temperature≈0.7, top_k=40` instead of greedy decoding would give a more
  honest read on what the adapter actually learned.
- Scale up: more instruction data (tens of thousands of examples), a more diverse instruction
  mix, and pre-training on general prose rather than only stories.
